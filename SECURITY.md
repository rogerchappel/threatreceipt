# Security scope

ThreatReceipt is a teaching fixture runner with an optional actual PostgreSQL adapter. It intentionally includes vulnerable behavior activated only through `--fixture vulnerable --execute`. The HTTP server binds to 127.0.0.1 on an ephemeral port, exists only for the command lifetime, uses synthetic data and supports only GET requests. Other processes on the same host can reach loopback; use an isolated development environment if that matters to your use.

There is no application target flag, shell-command execution, dynamic plugin loader, production probing, telemetry or production credential handling. External/reviewed PostgreSQL SQL is disabled pending independent privilege-boundary approval; see [database lifecycle and limitations](docs/postgres.md). The adapter starts only disposable clusters, without TCP or inherited database settings. PostgreSQL tooling below 16.15 is rejected; earlier draft revisions accepting external SQL are not approved for use. Development tooling uses pinned versions and a lockfile. Do not put secrets in manifest labels, which appear in reports.

If reporting a problem, provide only a minimal synthetic reproduction. Do not publish credentials, customer information, real exploit targets or sensitive response bodies in a public issue. Contact the repository owner to arrange a private disclosure channel before sending sensitive details. No private-reporting setting is assumed or changed by this project.
